# 多语言二轮报告（task-9）

用户原话：「语言切换为其他语言部分地方还是只有简体中文文本内容，包括各种地方；
还有英文模式下部分地方的按钮或者ui大小有问题例如收藏页的导入和导出按钮
如果能缩写尽量缩写或者换个方法。」

负责人：lead（原 owner cards-fe 连续 20+ 小时零产出，收回自做）。

---

## 一、排查方法论（三次纠正才走对，这段是本文最有价值的部分）

### 1. 键集合审计：0 缺口
14 个模块 × 3 语对比 → **zh_CN 有的键 en_US/zh_TW 全都有**。
所以问题**不是语言包缺键**，而是"有键但代码没调用"或"代码硬编码绕过了 t()"。
（如果只做到这一步就收工，会得出"没有漏翻"的错误结论。）

### 2. 渲染态扫描：第一次给出 282 处 → 全是假阳性
写 `test_i18n_english_leak.mjs` 切 English 逐页扫可见文本，第一版报 282 处。
**根因是探针自己的 bug**：jsdom **不实现 `window.fetch`**，而 mock 的
`i18n.bundle` 内部用 `fetch('/mock/i18n')` → 语言包根本没加载 →
页面上**每一个** `t()` 都退回代码里的中文兜底。

正解（照搬已跑通的 settings_probe）：用 jsdom 支持的 `XMLHttpRequest` 取语言包。
（也不能把整包 JSON 塞进 `?js0=` —— 会超 http.server 的请求行上限，直接 414。）

### 3. 加了"自证"才拿到真数据
现在探针开头强制验证两件事，任一不满足就 **abort 并声明本轮结果作废**：
```
bundle 直调: ok = true modules = 14
语言包自检 t(search) = "Search" （已加载）
```
（`t()` 是挂载**之后**异步加载的，所以要轮询最多 12 秒再判，否则又是竞态误判。）

结果：**13 个页面全部干净**（0 处可见中文残留）。

### 4. 但渲染扫描有天然盲区 → 补源码级守卫
扫描器只能扫**已经渲染出来**的文本。`toast(result.error || '删除失败')`
这种要等错误发生才显示的兜底，扫不到。所以另加：
- `test_r2_visual_css.mjs` 的 [7] 段：源码级断言"不许有 `|| '裸中文'` 兜底"，
  并显式排除 `t('key','中文')` 的合法 fallback。
  **这条守卫当场抓到一处我漏改的**（`toast(text || '新建收藏夹失败')`，
  变量名不同所以没进我的替换列表）—— 这就是它的价值。
- `test_ai_error_i18n.py` 的 [7] 段：**不桩 `_text()`**、走真实 `LanguageManager`
  的端到端断言。它抓到两个真 bug（见下）。

## 二、修掉的漏翻清单

### A. 前端渲染层（扫描器抓到）
| 位置 | 现象 | 修法 |
|---|---|---|
| `index.html` 标题栏 3 个按钮 | `aria-label="最小化"` 硬编码；最大化/还原连 t() 都没走 | 全改 `t()`；新增 `title_maximize`/`title_restore` |
| `app.js` 资源库错误兜底 | `'资源库读取失败'` 硬编码 → 英文界面出现「Could not load the cloud resource library: {err}**资源库读取失败**」中英混排 | 新增 `resource_load_failed_plain`/`resource_api_not_ready` |
| `trayLabels`（托盘浮层 4 项） | 初始值硬编码中文，后端 labels 要等用户点托盘才推来 → 英文界面从启动到第一次点托盘整排中文（呼出主窗口/呼出搜索框/呼出AI/退出） | 初始值留空 + `trayLabel(key)` 走 `t(key,…,'nav')`；**语言包 nav 三语早就齐全，没新增键** |
| 模型弹层分组名 | 后端 `providers.py` 的 label 是简体中文，前端直接渲染 | 新增 `aiProviderLabel()` 按 id 取 `ai_provider_<id>`（三语已有） |
| `introLines`（介绍 5 条）/`qqGroups`（QQ 群名） | **普通数组**，setup 时就把中文冻结，切语言不生效 | 改 `computed + t()`；群名复用语言包已有的 `qq_group_label`/`qq_report_label` |
| `REPO_PLATFORMS` 自定义/不开源 | 同上 | 改 `computed + t()`（GitHub 等专名不翻）；3 处 `.find()` 补 `.value` |

### B. 前端 toast / 状态变量兜底（源码级守卫抓到，共 16 处）
`该功能`+整句 needApi、对话框默认`取消`/`确定`、`（空）`、
`收藏失败`/`移动失败`/`创建失败`/`重命名失败`/`删除失败`/`保存失败`/
`新建收藏夹失败`/`读取 API Key 失败`/`清空失败`/`下载失败`/`未知错误`
→ 全部包进 `t()`，新增 15 个 `common` 键（三语）。

### C. 后端固定回复与错误（用户"包括各种地方"的主体，前端 grep 永远查不到）
这些是**后端生成、直接落盘进气泡**的文本，前端只负责显示、翻不了：
- `desktop/api/ai.py` 新增 `_text(key, fallback, module="settings", **fmt)`：
  按 `_locale()`（优先 `shell.current_language()`，"跟随系统"才准）取当前语言文案。
- 新增 `_localized_error(kind, message, status)`：按 client 的 **kind** 查表重写
  （12 个 kind 全覆盖），**保留 client 拼的「（服务端说明：…）」尾巴** ——
  那是排查 401 最有用的原始信息，本地化不能吞掉；认不出 kind / 缺键 → 原样返回。
- 三条固定回复（chat / polish / test）+ `client.py` 的 401 文案都接进语言包。
- 新增键：`ai_err_*`（12 kind + failed + current_config）、`ai_no_key_chat/polish/test`、
  `ai_key_invalid`（三语）。

**★ 可点击 token 的字面量按语言各写一份**：中文 `请填写<API Key>`、英文 `fill in <API Key>`。
如果英文界面里还写中文 token，就又成了用户报的"露简体中文"。
前端 `AI_SETTINGS_TOKENS` 全部认，且**必须按长度降序排**
（否则 `请填写<API Key>` 会被裸 `<API Key>` 先匹配掉，链接文字少一截）。

### D. 端到端测试抓到的两个真 bug（都在 C 的实现里，我自己写的）
1. **模块名写错**：`LanguageManager` 的模块键是 **`settings`**（映射到 set_language.json），
   我 `_text` 默认写成 `"set"` → **永远查不到、静默退回中文**，整个后端本地化等于没做，
   而且不报错、极难发现。桩版测试（[3][6]）**全都测不出来**，只有走真实 manager 的 [7] 抓到。
2. **`get_text` 找不到键时返回键名本身**（其 docstring 明写"找不到就返回 key"），
   我把它当有效文案用了 → 语言包缺键时用户气泡里会显示 `ai_no_key_chat` 这种字符串。
   现在 `got.strip() != key` 才算取到。

## 三、英文模式按钮尺寸（用户举例：收藏页导入/导出）

两处一起改（缺一不可）：
1. **文案缩写**：`en_US` 的 `fav_export` `"Export favorites"` → `"Export"`，
   `fav_import` `"Import favorites"` → `"Import"`。
2. **让按钮能收缩**：`.fav-ops-row .btn-half` 加 `min-width: 0` + `overflow: hidden`
   （flex 子项默认 `min-width:auto`，不写这个再短的文案也会撑破窄栏）。
   ⚠️ **没有写死宽高**（AGENTS 第 5 条禁止），靠 flex 收缩 + 省略号自适应。

## 四、明确未做（需要单独设计，不是漏做）

1. **数据结构取值不许翻译**：`makerPlatforms`（全平台/其他）、`CATEGORY_ORDER`（类别名）、
   `SYSTEMS`/`ARCHITECTURES`、`DEPLOY_STATES` 等 —— 它们会**存进资源库 JSON、
   后端按它匹配**（`resource_schema.py` 是事实来源），翻译会破坏数据与检索。
   要做"值→显示"映射表得单独设计（涉及资源库 schema 与检索），本轮不做。
2. `en_US` 包内还有 4 条 maker 长说明文本里带中文（其中一条**键名本身是中文**），
   属既有的低优先项，改动面大（要重排键名），本轮未动。
3. 后端其余 ~30 处 `_fail("中文…")`（maker / plugins / log / notice / 存储迁移等）：
   前端**大多已有自己的 t() 兜底**（`result.error || t('xxx_failed', …)` 里
   error 优先），彻底本地化需要给每个域加 `_text` + 建键表，属独立一轮工作量。
   本轮只做了用户直接会看到的 AI 那批 + 前端兜底。
